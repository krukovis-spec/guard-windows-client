# Guard Parent MVP - рабочая проверка

## Что готово

- Installer: `Output/Guard-Setup-v1.0.0.exe` (latest Codex compile: 2026-06-07 13:29, 2717786 bytes).
- После установки Guard запускается через `StartHelperG.exe`.
- На непривязанном компьютере Guard показывает pairing code.
- Родительский кабинет доступен в браузере по LAN-адресу, который показан в окне pairing code.
- Первый вход в кабинет: pairing code + новый родительский пароль.
- Открытый родительский кабинет сам обновляется примерно раз в 15 секунд, если родитель не печатает в поле.
- Сессия родительского кабинета истекает через 5 минут; автообновление страницы не должно держать её живой бесконечно.
- Опасные действия требуют повторного ввода родительского пароля: `Maintenance mode`, выключение блокировки, ослабление AppControl, разрешение приложений/сайтов, смена PIN, лимиты, задачи и Windows account.
- После LAN-привязки включается локальный режим: старый updater/log sender не ходит на `guard.alexweb.app`.
- После входа можно:
  - работать в режиме `default deny`: неизвестные приложения и сайты по умолчанию закрыты до решения родителя;
  - добавить домен в блокировку;
  - удалить домен из родительского списка;
  - включить/приостановить блокировку;
  - включить `Maintenance mode`: временно отключить все защиты на выбранное время и потом вернуть прежние правила;
  - сменить emergency PIN;
  - выбрать Windows-пользователя ребёнка и безопасно перевести его из админов в обычного пользователя, если найден отдельный родительский админ;
  - включить контроль приложений через AppLocker;
  - разрешить конкретный `.exe` постоянно или на время;
  - видеть запросы приложений от ребёнка и одобрять их на 15/60 минут или навсегда;
  - видеть запросы сайтов/доменов от ребёнка и одобрять их на 15/60 минут или навсегда;
  - отзывать активные разрешения сайтов;
  - видеть сегодняшнюю активность по приложениям;
  - видеть сегодняшнюю активность по сайтам, когда Guard может прочитать домен активного браузерного окна;
  - назначать категории приложений/сайтов и дневные/session лимиты;
  - добавлять ежедневные задачи с бонусными минутами.

## Ограничения MVP

- Кабинет работает по домашней сети/LAN через HTTP, не через HTTPS.
- Для доступа из интернета нужен следующий этап: облачный сервер с HTTPS и нормальной авторизацией.
- Старый upstream assign-flow в коде не удалён, но для LAN-привязки Ивана используется локальный режим.
- Windows Firewall может спросить разрешение на входящие подключения к Guard. Для проверки с родительского ПК в той же сети его нужно разрешить.
- Installer сейчас использует admin install и HKCU autostart. Для первой проверки запускай установку под тем Windows-пользователем, где Guard должен автоматически стартовать.
- Для контроля приложений ребёнок должен работать под обычным Windows-пользователем, не администратором. Пароль администратора должен быть только у родителя.
- В кабинете есть блок `Windows account`: сначала выбери детский Windows-аккаунт, потом нажимай conversion только если Guard показывает, что отдельный админ найден.
- Контроль приложений использует Windows AppLocker. Если AppLocker/PowerShell cmdlets недоступны на конкретной редакции Windows, Guard покажет ошибку применения в диагностике.
- Режим `Enforce` меняет локальную AppLocker policy. Новая LAN-привязка включает его сразу; если настраиваешь уже обжитый ПК, сначала можно временно включить `Maintenance mode`, добавить нужные приложения и затем вернуться в `Enforce`.
- Кнопка `Off` очищает локальную AppLocker policy, созданную для проверки. Guard перед применением пишет backup XML в `%APPDATA%\Guard\applocker`.
- `Task Manager` и основные системные инструменты управления процессами (`taskkill`, `cmd`, PowerShell и т.п.) по умолчанию блокируются в AppControl-режиме. Разрешать это окно обслуживания нужно только временно через родительский кабинет.

## Рекомендуемый порядок на детском ПК

1. Не сбрасывай Windows к заводским настройкам без причины. Сброс нужен только если на ПК уже хаос: неизвестные админ-аккаунты, много левых программ, сломанные права или хочется полностью чистый старт.
2. Оставь Microsoft Defender/Microsoft Security включённым. Guard не заменяет антивирус, он управляет доступом к сайтам и приложениям.
3. Если включён Microsoft Family Safety и он мешает постоянными подтверждениями, лучше после проверки Guard отключить именно Family Safety-ограничения, а Defender оставить.
4. Создай или проверь отдельный родительский Windows-аккаунт администратора.
5. Ребёнок должен входить под отдельным обычным Windows-пользователем. Если сейчас он админ, сначала привяжи Guard, затем в кабинете `Windows account` переведи ребёнка в обычного пользователя.
6. До жёсткого режима установи и войди во все учебные программы и аккаунты: браузер, онлайн-школа, Контур Толк, нужные учебные приложения.
7. Установи Guard, привяжи детский ПК к родительскому кабинету: новая привязка сразу включает строгий режим `Enforce` + web default-deny.
8. Добавляй нужные приложения и сайты через заявки ребёнка или временно через `Maintenance mode`.
9. Для настройки, установки обновлений или новых программ используй `Maintenance mode`: нажал `Unlock all temporarily`, сделал работу, затем `End maintenance now` или дождался таймера.

## Как проверить

1. На детском ПК запустить `Output/Guard-Setup-v1.0.0.exe` от имени администратора.
2. В конце установки оставить включенным `Launch Guard now`.
3. Дождаться окна `Pairing code`.
4. На родительском ПК открыть один из URL, показанных в этом окне, например `http://192.168.x.x:8765/`.
5. Ввести pairing code и задать родительский пароль длиной минимум 12 символов.
6. В кабинете добавить домен, например `example.com`.
7. Проверить, что домен появился в списке и статус `blocking enabled`.
8. Для реальной проверки блокировки добавить нужный домен, например `youtube.com`, и дождаться применения правил.
9. На детском ПК через tray пункт `Request Site Access` отправить запрос домена, например `vk.com`.
10. В кабинете в `Access requests` одобрить сайт на `15 min`, `60 min` или `Always`.
11. В `Allowed sites` проверить активное разрешение; при необходимости нажать `Revoke`.

## Как проверить контроль приложений

1. На детском ПК убедиться, что ребёнок входит в Windows как обычный пользователь, не администратор.
2. В родительском кабинете открыть раздел `Applications`.
3. Нажать `Audit`.
4. Добавить постоянные разрешения для нужных приложений, например браузер/школьная программа/игра:
   - `App name`: понятное имя;
   - `Exe path`: полный путь к `.exe` на детском ПК.
5. Для игры на время использовать `Allow temporarily`: указать путь к `.exe` и минуты.
6. После проверки списка нажать `Enforce`.
7. Для установщика, который нужно разрешить один раз, выдать временное разрешение на его `.exe`; после истечения времени Guard уберёт разрешение из policy.
8. Последние 5 минут Guard показывает отдельные предупреждения `5 / 4 / 3 / 2 / 1 min`, чтобы ребёнок успел сохраниться.
9. После истечения времени запущенный процесс будет остановлен.

## Как временно отключить все защиты для обслуживания

1. В родительском кабинете открой верхний блок `Maintenance mode`.
2. Укажи минуты, например `30`.
3. Нажми `Unlock all temporarily`.
4. Guard попросит родительский пароль ещё раз.
5. На это время Guard приостанавливает блокировку сайтов, контроль приложений и блокировку Task Manager/system tools.
6. Списки разрешённых приложений, сайтов, лимитов и задач не удаляются.
7. После окончания таймера Guard возвращает прежнее состояние и заново применяет правила.
8. Если закончил настройку раньше, нажми `End maintenance now`.

## Как защитить родительский компьютер

- Guard не может сам заблокировать Bitwarden: сайт в браузере не должен управлять расширением паролей.
- Лучший вариант сейчас: длинный пароль кабинета в Bitwarden + авто-блокировка Bitwarden через короткий таймаут или при блокировке Windows.
- На родительском ПК поставь привычку `Win+L`, когда отходишь.
- В Bitwarden лучше включить vault timeout `On system lock` или короткий таймаут вроде 5 минут.
- PIN хуже пароля как основной способ: его проще подсмотреть и потом использовать без Bitwarden.
- Google/Yandex Authenticator можно добавить следующим этапом для второго фактора, но для первого рабочего MVP уже есть повторный пароль на опасные действия.
- На родительском телефоне скрыть текст уведомлений на заблокированном экране, особенно для почты и мессенджеров. Коды восстановления не должны читаться из шторки без разблокировки.
- В Guard emergency PIN меняется только через родительский кабинет после повторного ввода родительского пароля. Серверные `pinCode` из старого upstream-режима игнорируются, старый remote-updater выключен по умолчанию, пункт `Привязать через сервер` убран из UI.

## Как временно разрешить только Task Manager/system tools

1. В родительском кабинете открыть `Applications`.
2. В блоке `Task Manager and system tools` указать минуты, например `10`.
3. Нажать `Allow temporarily`.
4. После окончания времени Guard снова заблокирует Task Manager и системные инструменты управления процессами.
5. Если нужно закрыть доступ сразу, нажать `Block now`.

## Что ожидать от AppLocker-режима

- Новые `.exe` из Downloads/AppData не должны запускаться, если они не разрешены.
- Скачанный другой браузер не должен обходить сайт-блокировки, если его `.exe` не разрешён.
- Установщик Minecraft/Yandex/другого приложения нужно разрешать явно и лучше временно.
- Windows и сам Guard добавляются в разрешённую базу автоматически.
- Не включай `Enforce` с пустым списком нужных приложений: ребёнок сможет запускать Windows/Guard, но прикладные программы могут быть заблокированы.
- Task Manager, `taskkill`, `cmd`, PowerShell и похожие системные инструменты получают отдельные deny-rules, потому что стандартные Windows allow-rules иначе могут разрешить обход защиты.
- Если ребёнок запускает неразрешённое приложение, Windows блокирует запуск, а Guard показывает ребёнку окно “попросить доступ” и после подтверждения создаёт request в `Access requests`.
- Ребёнок также может вручную отправить request через tray пункт `Request App Access`.
- Если ребёнок открывает неизвестный сайт в поддерживаемом браузере, Guard читает домен из адресной строки, показывает окно “попросить доступ”, закрывает браузер и добавляет скрытое правило блокировки до решения родителя.
- Ребёнок также может вручную отправить request через tray пункт `Request Site Access`; родитель одобряет его в том же блоке `Access requests`.
- Временное разрешение сайта исключает домен из блокировок, а после истечения Guard помечает правила на пересборку и сайт снова блокируется.
- Если сайт привязан к категории, например `Video`, то дневной/session лимит этой категории также может вернуть сайт в блокировку.
- Tray пункт `My Tasks` показывает ежедневные задачи. Self-report задача засчитывается по кнопке ребёнка; verified app task засчитывается только если накопилось нужное активное время в указанном `.exe`.

## Активность, лимиты и задачи

- Guard считает активное foreground-приложение, заголовок окна, категорию и idle-секунды.
- Для известных браузеров Guard пытается прочитать домен из адресной строки активного окна через Windows UI Automation и считает его как `site:domain`.
- Если Windows/браузер не отдаёт URL, Guard считает время как обычное приложение-браузер, а не как конкретный сайт.
- Содержимое нажатых клавиш не записывается.
- История браузера не читается.
- Idle-интервалы не считаются как активное время.
- В кабинете `Today activity` показывает приложения/сайты за день и позволяет назначить категорию.
- В `Allowed sites` можно заранее назначить категорию сайту, например `Video`.
- В `Time limits` можно задать общий дневной screen-time и лимиты категории, включая session minutes.
- Сайт-лимиты реально останавливают доступ, если сайт открыт через разрешение. В web default-deny неизвестный домен сам становится скрытым blocked-domain правилом, поэтому после истечения разрешения или лимита он снова закрывается.
- Бонусы от задач увеличивают лимит выбранной категории на текущий день.
- Проверяемые задачи, например симулятор дрона, требуют реального активного времени приложения.

## Детский Windows-пользователь

- Ребёнок должен работать под обычным Windows-пользователем.
- В кабинете есть блок `Windows account`: укажи детский Windows-аккаунт и сохрани.
- Guard читает локальную группу администраторов и показывает, можно ли безопасно перевести ребёнка в обычного пользователя.
- Кнопка conversion появляется только если выбранный ребёнок сейчас админ и найден отдельный админ.
- Codex проверил этот flow только через fake runner. Живое изменение Windows-пользователей не запускалось.
- Нельзя демоутить “текущего пользователя” вслепую: если installer запущен с родительскими admin-credentials, текущим пользователем может оказаться родитель. Поэтому аккаунт выбирается явно в кабинете.

## Если не открывается с родительского ПК

- Проверь, что оба ПК в одной сети.
- Открой URL с IP-адресом детского ПК, не `localhost`.
- Если Windows Firewall показал запрос, разреши доступ для частной сети.
- Если окно показывает только `localhost`, значит Guard смог запустить кабинет только локально; тогда для LAN нужен запуск с admin-правами или отдельная настройка Windows URL ACL/firewall.
