# Окно подготовки Guard для Windows

`Guard.Setup` — отдельное окно для проверки установленной службы, экспорта публичного описания компьютера и привязки родительского телефона по QR. Это **не установщик и не готовый мастер семейного подключения**. Выбор детского аккаунта, включение защиты и Recovery Kit здесь ещё не подключены; QR-сценарий пока проверен сборкой и автоматическими тестами, не настоящим телефоном.

Сборка без запуска: `dotnet build src/Guard.Setup/Guard.Setup.csproj -c Release`. Использованы встроенный [WPF в .NET Desktop SDK](https://learn.microsoft.com/en-us/dotnet/core/project-sdk/msbuild-props-desktop) и одобренный Иваном [QRCoder 1.8.0](https://www.nuget.org/packages/QRCoder/1.8.0). `PngByteQRCode` создаёт PNG в памяти: нет внешнего генератора, браузера, файла или копирования QR в буфер обмена. У пакета есть транзитивные зависимости; аудит NuGet с ними на 05.10.2026 не обнаружил известных уязвимостей.

## Проверка в одноразовой VM

Только после установки доверенного комплекта службы в VM: открыть `Guard.Setup.exe` и подтвердить UAC. У службы должны быть нормальная конфигурация SCM без одноразовых установочных аргументов и защищённые файлы. На основном ПК этот исполняемый файл не запускать.

1. Нажать «Проверить установку». Окно проверяет настоящий SCM/SYSTEM endpoint, читает статус и условия настройки. Оно не запускает службу и не применяет политики. Разные версии состояния двух ответов отклоняются; можно проверить заново. При отмене или ошибке прежние результаты убираются.
2. Для ещё не начатой настройки нажать «Сохранить описание компьютера…». Служба заново проверяет первоначальное состояние; выпуск без настроенных публичных pins откажет. Выбрать **новое** имя файла в локальной папке. Перезапись, UNC, ADS, обнаруженные перенаправления и неоднозначные имена запрещены. При ошибке записи частичный файл может остаться: не использовать его, повторить с новым именем.
3. На доверенном компьютере оператора использовать [Guard.Provisioning](../../tools/Guard.Provisioning/README.md). Перед подготовкой профиля независимо проверить адрес сервера выпуска и сверить **все 64 символа SHA-256** с этим окном. Код вычислен по точным байтам сохранённого файла; копирование/переформатирование JSON меняет его. Сам файл и хеш не доказывают владение компьютером.

Описание содержит только публичные идентификаторы, адрес и открытые ключи. В окне нет полей для Cloudflare API-токена, административного mailbox-токена, пароля Bitwarden или приватных ключей. Адрес принимается из аутентифицированной службы, а не используется для сетевой авторизации из окна. Оператор всё равно должен проверить origin независимо.

Закрытие окна отменяет только локальный запрос. Ни кнопка закрытия, ни успешное чтение, ни привязка родителя не включают/отключают защиту. Постоянная надпись «Защита не подтверждена» сохраняется даже при всех выполненных условиях: наблюдение readiness не является доказательством действующих блокировок или стойкости к администратору.

## Привязка телефона в лаборатории

После подготовки подключения оператором и успешной проверки ещё не настроенной службы:

1. Нажать «Привязать телефон». Окно сохраняет одноразовое полномочие подтверждения только в памяти; QR появляется после проверенного ответа службы. Отсканировать его приложением Guard на родительском телефоне и пройти подтверждение на телефоне. Срок попытки виден рядом с QR.
2. Сверить **все восемь строк** на компьютере и телефоне. Отметить «Я сравнил…» и отдельно нажать «Подтвердить привязку». При несовпадении нажать «Отменить привязку»; эта кнопка отменяет только незавершённую попытку, не владельца или защиту.
3. Проверить результат на телефоне. Сохранённая привязка ещё не означает рабочую доставку разрешений или включённые блокировки. Дальнейшие подготовка, активация и защищённая передача профиля описаны в операторской инструкции.

QR и код сравнения скрываются при потере фокуса, истечении срока, ошибке или закрытии окна. После возвращения код нужно сравнить заново. Опрос не подтверждает привязку автоматически и не обновляет экран во время сравнения. Потерянный ответ подтверждения сначала проверяется чтением; повторная отправка не выполняется вслепую. После потери ответа начала/отмены нельзя сразу начинать новую попытку; окно показывает дальнейшее действие. Перезапуск окна не восстанавливает секрет подтверждения и не сбрасывает владельца.

## Проверено и осталось

После завершённой native-привязки нажать «Проверить установку»: станет доступна кнопка «Сохранить подтверждение привязки…». Read-only verb 39 возвращает публичный подписанный GNA1 только для уже закреплённого владельца; нет выбранных вызывающим ключей, сети или изменения состояния. Окно использует тот же authenticated SCM/SYSTEM client, показывает срок и полный SHA-256, сохраняет без перезаписи/перенаправленных путей и отказывает, если срок истёк во время диалога. Файл нужно проверить на родительском ПК командой `Guard.Provisioning verify-native` с исходным приватным заданием компьютера. Подробности и границы — [операторская инструкция](../../tools/Guard.Provisioning/README.md). Это ещё не передача рабочих прав телефону.

- Release-сборка XAML/C#; логика чтения/версий/отказов/отмены и экспорт точных байтов проверяются существующим `Guard.Windows.Ipc.Tests`. Общий валидатор описания используется также оператором; его сквозная проверка остаётся в `Guard.Windows.Crypto.Tests`.
- На 05.10.2026 общий безопасный набор: Release, 29 v2 harnesses и 45 legacy checks PASS. Существующий IPC harness проверяет настоящий локальный PNG и все 11 состояний экрана, полный код и истечение срока; сессия проверяет потерянные ответы, версии и отмену без запуска WPF/SCM. Self-review исправил выключенные после потери фокуса кнопки до начала сессии и обработку ошибки рендеринга при возвращении окна. Визуальная/камерная проверка остаётся отдельно.
- Настоящее окно, UAC, установленный SYSTEM endpoint, фокус/скринридер/масштабирование и сохранение через диалог требуют VM-проверки. На основном ПК окно не запускалось. Криптографические проверки и сборка это не заменяют.
- [Отдельный VM-маршрут](../../scripts/lab/service-bootstrap.md) 05.10.2026 подтвердил настоящий SYSTEM bootstrap, аутентифицированное чтение/экспорт и перезапуск службы. Первоначальная отмена UAC больше не является блокером. Это проверка клиента/модели без графического окна, не приёмка интерфейса, телефона или действующих блокировок.
- Русские тексты и системные контрастные цвета, прокрутка содержимого и доступные стандартные кнопки уже есть. Полный Codex-подобный визуальный проход по Windows/Android/PWA остаётся M7; точное визуальное совпадение пока не проверено.
