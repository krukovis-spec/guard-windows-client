# Guard.Child

Непривилегированное окно запроса доступа к программе. Открывается из выбранного обычного аккаунта Windows, без UAC.

1. Нажать «Обновить список».
2. Выбрать недавнюю блокировку и при желании написать короткое пояснение.
3. Нажать «Попросить доступ». Подтверждение означает только сохранение в локальной очереди, не доставку родителю и не разрешение запуска.

Потерянный ответ можно повторить: служба сохраняет исходный действующий запрос без изменения срока. Перезапуск/закрытие окна не меняет защиту. В этой версии окно ещё не показывает итоговые решения/квитанции; автоматический запуск в защищённых сессиях относится к установочному M6 gate.

Клиент использует только фиксированный child pipe, проверяет владельца SYSTEM, точную работающую службу/процесс и связь ответа с запросом. Приложение не читает журналы ОС, не принимает пользовательский путь/hash как доказательство блокировки и не меняет системные настройки.

**До подключения проверенного active-policy источника M1 служба возвращает «список недоступен».** Пустой список и работающее окно не доказывают активную защиту. На основном ПК рабочий клиент не запускаем: для отладки есть отдельный стенд ниже.

Безопасная проверка реального XAML и обработчиков на вымышленных данных:

```powershell
dotnet run --project tools/Guard.Child.Preview -c Release -- --check
```

В стенд не включены production entry/backend или Guard.Windows; нет IPC/сети/изменений системы. Тестовые окна закрываются по окончании, снимок сохраняется во временный каталог и его путь выводится в терминале.
